# 04 — Solver Design

The solver lives in `api/src/Solver` and is **pure**: it takes a
`SolverInput` and returns a `SolverOutput`. It has no knowledge of EF, HTTP or DTOs.

Engine: **Google OR-Tools CP-SAT** (`Google.OrTools.Sat`).

> **Agents: write the model in text first.** Before coding any stage, the implementing
> agent must update the relevant section here if it deviates (variables, constraints,
> objective). Bugs in the model are far harder to find by debugging C#.

## 1. Input / output model (`Solver/Model/`)

```csharp
public sealed record SolverInput(
    IReadOnlyList<SolverRoom> Rooms,
    IReadOnlyList<SolverParticipant> Participants,
    IReadOnlyList<SolverRule> Rules,
    IReadOnlyList<SolverPin> Pins,
    SolveOptions Options);

public sealed record SolverRoom(
    Guid RoomId, Guid CenterId, decimal Cost,
    RoomLayoutModel Layout);                     // seats are generated by Layout/SeatGenerator

public sealed record RoomLayoutModel(
    int Rows, int Columns, int SeatsPerDesk,
    IReadOnlyList<int> AislesAfterColumns,
    IReadOnlySet<string> DisabledSeats,
    IReadOnlySet<string> AccessibleSeats);

public sealed record SolverParticipant(
    Guid ParticipantId,
    IReadOnlyDictionary<string,string> Attributes, // resolved attribute key → value (keys come from rules)
    bool NeedsAccessibleSeat,
    string SortKey);                                // "LastName FirstName MiddleName" for deterministic expansion

public sealed record SolverRule(
    Guid RuleId, RuleType Type, bool IsHard, int Weight, RuleParameters Parameters);   // typed, see §2

public sealed record SolverPin(Guid ParticipantId, Guid RoomId, string? SeatKey);

public sealed record SolveOptions(
    int Alternatives = 5,
    double DiversityRatio = 0.10,      // min share of participants that must move between alternatives
    double CostSlack = 0.10,           // alternatives may cost up to +10% vs best
    int Stage1TimeLimitSeconds = 60,
    int Stage2TimeLimitSecondsPerRoom = 5,
    int MaxFeedbackIterations = 5,
    int NumWorkers = 0,                // 0 = all cores
    int RandomSeed = 42,
    ObjectiveMode ObjectiveMode = ObjectiveMode.CostThenSoft);

public sealed record SolverOutput(
    SolveStatus Status,                 // Optimal | Feasible | Infeasible | NoSolutionInTime | Cancelled
    IReadOnlyList<SolvedAllocation> Allocations,  // [0] = best
    IReadOnlyList<Diagnostic> Diagnostics,
    SolveStats Stats);

public sealed record SolvedAllocation(int Index, IReadOnlyList<SeatAssignment> Items, ObjectiveBreakdown Objective);
public sealed record SeatAssignment(Guid ParticipantId, Guid RoomId, string SeatKey);
public sealed record ObjectiveBreakdown(int RoomsUsed, decimal Cost, long SoftPenalty, IReadOnlyDictionary<Guid,long> PenaltyByRule);
public sealed record Diagnostic(DiagnosticCode Code, DiagnosticSeverity Severity, Guid? RuleId,
    IReadOnlyDictionary<DiagnosticArgument, string> Arguments);   // message rendered from resources by Code
```

Progress is reported through `IProgress<SolveProgress>`:

```csharp
public sealed record SolveProgress(SolveStage Stage, double? Percent,
    double? Objective, double? BestBound, int? RoomsDone, int? RoomsTotal, int? AlternativesDone);
public enum SolveStage { Precheck, Stage1, Stage2, Feedback, Alternatives, Expanding, Done }
```

The enum order is not the reporting order: the pipeline reports Precheck → Stage1 → Stage2
(→ Feedback → Stage2 …) → Expanding → Alternatives → Done (§8a). Nested solves of the
alternatives generator report nothing; only `Alternatives` with `AlternativesDone`.

Progress carries no message text: clients derive the label from `SolveStage` (i18n) and the
numeric fields, so `SolveProgressDto` has no `message` either.

Entry point: `SolverPipeline.RunAsync(SolverInput, IProgress<SolveProgress>, CancellationToken)`.

## 2. Rule catalog

| Id | `RuleType` | Hard/Soft | Parameters (JSON) | Stage | Penalty unit (soft) |
|----|------------|-----------|-------------------|-------|---------------------|
| R1 | *(implicit)* Capacity & coverage | hard, always | – | 1, 2 | – |
| R2 | `SeparateByAttribute` | both | `{ "attributeKey": "group", "scope": "Room"\|"Center", "maxPerScope": 1 }` | 1 | per participant over limit |
| R3 | `NoAdjacentByAttribute` | both | `{ "attributeKey": "group", "adjacency": ["SameDesk","Side","FrontBack","Diagonal","SideAcrossAisle"], "seatLevelSide": false }` | 1 (bound) + 2 | per violating seat pair |
| R4 | `AccessibleSeating` | hard only; auto-added when any participant needs it | `{}` | 1, 2 | – |
| R5 | `MinRoomFill` | soft only | `{ "minFillRatio": 0.6 }` | 1 | per missing seat |
| R6 | `KeepTogetherInCenter` | soft only | `{ "attributeKey": "school" }` | 1 | per extra center used by a value |
| R7 | *(implicit)* Pins | hard, always | from `Pin` table | 1, 2 | – |
| R8 | `SpreadInRoom` | soft only | `{ "adjacency": ["Side"] }` | 2 | per occupied adjacent pair |
| R9 | `FillFromFront` | soft only (tie-breaker) | `{}` | 2 | Σ row index of occupied seats |

Parameters are typed on both sides of the boundary:
- `Domain/Rules/Parameters/*` — abstract `RuleParameters` + one sealed record per `RuleType`
  (JSON-polymorphic on `type`, stored as jsonb), using the `AttributeKey` value object
  (`AttributeKeys.Group` / `AttributeKeys.School` constants for built-ins).
- `Solver/Model/RuleParameters.cs` — the same shapes with primitive types (the solver
  references nothing in the repo). `Application/Solving/Services/SolverInputBuilder` maps one
  to the other; the solver never contains attribute-key literals, it only uses keys it receives.
- Invariants are validated by the FluentValidation validators of `CreateRuleCommand` /
  `UpdateRuleCommand` (one child validator per parameters type).

Missing attribute value (participant has no `group`): treated as a **unique value** (never
conflicts with anybody) and a `Warning` diagnostic `AttributeMissing` is emitted with counts.

Later (not MVP): `R10 MaxTravelDistance { maxKm }` using participant home coordinates.

## 3. Decomposition

A monolithic model with a boolean per (participant, seat) is infeasible at scale
(10 000 × 10 000). We solve in two stages with a feedback loop:

```
Precheck ─► Stage 1: participant classes → rooms (counts)
              │
              ▼
          Stage 2: for each room in parallel, classes → seats
              │  room infeasible?
              ├──yes──► add cut to Stage 1, re-solve (≤ MaxFeedbackIterations)
              ▼
          Expand classes → individual participants (deterministic)
              ▼
          Alternatives loop (repeat stage 1 + 2 with diversity constraints)
```

### 3.1 Participant classes

A **class** is a set of non-pinned participants that are interchangeable for every enabled
rule. Signature = (values of every `attributeKey` referenced by enabled rules,
`NeedsAccessibleSeat`). Participants with a missing value get a unique synthetic value, i.e.
their own class only if the missing key matters; otherwise they merge.

Implementation notes (WS-A):
- Referenced keys = `attributeKey` of enabled R2, R3, R6 rules. A value that is absent, empty
  or whitespace counts as **missing**. A missing key is simply **absent from
  `ParticipantClass.Values`**; consumers treat an absent key as a unique value (the class is
  never summed with any other class for that key). Each participant with a missing referenced
  key gets its own class (singleton).
- Pinned participants = every participant referenced by a pin; they never appear in classes.
- Classes are ordered deterministically by signature; `Index` = position in the list;
  `ParticipantIds` are ordered by `SortKey`, then id.

Notation: classes `k ∈ K`, size `s_k`; `val_a(k)` = value of attribute `a` for class `k`.
Typical sizes: 10 000 participants, attribute `group` only → |K| ≈ number of groups (~400).

Pinned participants are not in classes; they are constants: `pin_r` = number pinned to room
`r`, `pin_{a,v,r}` = pinned with value `v` of attribute `a` in room `r`, etc.

### 3.2 Room facts (precomputed, `Solver/Layout/`)

- `cap_r` = enabled seats; `acc_r` = enabled accessible seats.
- `E_r(kinds)` = adjacency edges for a set of kinds (see 03 → Seat adjacency).
- `α_r(kinds)` = size of a maximum independent set of the graph `(seats_r, E_r(kinds))`,
  computed by a small CP-SAT model (time limit 2 s), **cached by (layout hash, kinds)**.
  If not proven optimal, use the best found value (a lower bound — conservative; it may
  cost optimality, never feasibility).
  Implementation (`IndependentSetCalculator`): one CP-SAT worker, `x_p ∈ {0,1}`, `¬x_p ∨ ¬x_q`
  per edge, maximize `Σ x_p`, hinted with a greedy min-degree independent set whose size is
  also the fallback lower bound. Cache key = (rows, columns, seats per desk, aisles, disabled
  seats, kinds ∪ {SameDesk}, `seatLevelSide` when it can matter); thread-safe
  (`ConcurrentDictionary`). Cancellation throws `OperationCanceledException` (nothing cached).
- Seats (`SeatGenerator`) are the enabled seats in seat-key order (row, column, seat); a seat's
  position in that list is its seat index in `SeatEdge`. `seatLevelSide` refines only `Side`
  (not `SideAcrossAisle`); `SameDesk` is always included.

## 4. Stage 1 — classes to rooms (`Solver/Allocation/`)

**Variables**

- `y_r ∈ {0,1}` — room `r` is used (opened).
- `n_{k,r} ∈ [0, min(s_k, cap_r)]` integer — participants of class `k` in room `r`.
  Created only for eligible pairs (e.g. accessibility: if `k` needs accessible seats and
  `acc_r = 0`, no variable).

**Hard constraints**

1. Coverage: `Σ_r n_{k,r} = s_k` for every `k`.
2. Capacity: `Σ_k n_{k,r} + pin_r ≤ cap_r · y_r` for every `r`.
3. Pinned room forces open: `y_r = 1` if `pin_r > 0`.
4. R4 accessibility: `Σ_{k needs acc} n_{k,r} + pinAcc_r ≤ acc_r`.
5. R2 `SeparateByAttribute(a, scope, m)`, hard, for every value `v` and scope unit `u`
   (room `r`, or center `c` = all rooms of `c`):
   `Σ_{k: val_a(k)=v} Σ_{r∈u} n_{k,r} + pin_{a,v,u} ≤ m`.
6. R3 `NoAdjacentByAttribute(a, kinds)` stage-1 bound, hard, for every `v`, `r`:
   `Σ_{k: val_a(k)=v} n_{k,r} + pin_{a,v,r} ≤ α_r(kinds)`.
   (Necessary, not sufficient — stage 2 decides; see feedback loop.)
   Accessibility refinement: needs-accessible participants may only use accessible seats, so for
   every `v` and `r` additionally
   `Σ_{k: val_a(k)=v, k needs acc} n_{k,r} + pinAcc_{a,v,r} ≤ α^acc_r(kinds)`, where `α^acc_r` is the
   maximum independent set over the accessible seats of `r` only (`AlphaCache.GetAccessible`) and
   `pinAcc_{a,v,r}` counts pinned needs-accessible participants with value `v` in `r` (`PinFacts.AccessibleValue`). Without it, a value
   whose accessible members exceed `α^acc` passes stage 1, stage 2 is infeasible and the feedback
   loop cuts the wrong class.

**Soft constraints** (each adds a non-negative penalty variable)

- R2 soft: `excess_{v,u} ≥ Σ… − m`, penalty `w · Σ excess`.
- R3 soft: bound not applied in stage 1 (penalty arises in stage 2 only).
- R5 `MinRoomFill(p)`: `short_r ≥ ⌈p · cap_r − 1e-9⌉ · y_r − Σ_k n_{k,r} − pin_r` (same rounding as the validator, §10), penalty `w · Σ short_r`.
- R6 `KeepTogetherInCenter(a)`: `z_{v,c} ∈ {0,1}`,
  `Σ_{k: val=v} Σ_{r∈c} n_{k,r} ≤ s_v · z_{v,c}`; penalty `w · Σ_v (Σ_c z_{v,c} − 1)`.

**Objective** (`ObjectiveMode`)

- `CostThenSoft` (default, lexicographic):
  1. minimize `Cost = Σ_r cost_r · y_r` (costs scaled to integers ×100) → `C*`;
  2. add `Cost ≤ C*`, minimize `SoftPenalty = Σ penalties`.
  Both solves share the time limit (60 % / 40 %); the first solution is used as a hint for
  the second (`AddHint`).
- `Weighted`: minimize `1000 · Cost + SoftPenalty` in one solve.

**Symmetry breaking**: rooms with identical (layout hash, cost, center when R6 is active, no
pins) are ordered: `y_{r_i} ≥ y_{r_{i+1}}`.

Rooms whose layout hash and cost coincide are only interchangeable if no rule distinguishes
centers, so the center is part of the key whenever R6 **or a Center-scoped R2** is enabled.
Rooms with pins or with feedback cuts are excluded from symmetry groups.

**Redundant covering knapsacks** (stated explicitly, implied by coverage + capacity):
`Σ_r cap_r · y_r ≥ |P|` and `Σ_r acc_r · y_r ≥ |P_acc|` (pinned participants included). They
expose the room-selection knapsack to CP-SAT directly, so its objective bound reaches the optimum
quickly instead of being proved by search over the per-class counts.

**Greedy hint** (when no hint is given, i.e. not for alternatives): `y_r = 1` for pinned rooms, then
rooms in ascending `cost_r / cap_r` (ties: lowest index, matching the symmetry order) until the open
seats cover `|P|` and the open accessible seats cover `|P_acc|`; all other `y_r = 0`.

Measured effect (Bench medium, 2 cores): stage 1 from 12.5–15 s to 5.2–7.2 s (full run 8.7–12 s).
A complete greedy hint (class counts too) was tried and rejected: it conflicts with the symmetry
order and slowed medium to ~25 s. (Superseded by the two-step solve below, whose complete hint is
built for the selected rooms only and is consistent with the symmetry order.)

### 4.1 Two-step solve: room selection → assignment (Phase 3 H1, R-5)

Used for `CostThenSoft` when the request has no previous solutions and no `CostBound` (i.e. the
best allocation and its feedback re-solves; alternatives and `Weighted` keep the single model above).
On large (400 rooms × 508 classes ≈ 200 000 `n_{k,r}`) the single model spends its whole limit
without improving its first solution; the cost part of the problem, however, only depends on `y`.

**Step S — room selection on room types** (`RoomSelection`). Rooms are aggregated into *types*
`τ` by the symmetry key of §4 (layout hash — hence `cap`, `acc`, α — cost, and the center when R6
or a Center-scoped R2 is enabled). A room with pins or feedback cuts is a type of its own.
Variables `o_τ ∈ [pinnedRooms_τ, |τ|]` integer = number of open rooms of type `τ`.

```
minimize   Σ_τ cost_τ · o_τ
subject to Σ_τ cap_τ · o_τ ≥ |P|                    (all participants, pins included)
           Σ_τ acc_τ · o_τ ≥ |P_acc|
           Σ_τ ℓ_τ(a) · o_τ ≥ max_v s_v(a)           for every key a with a hard per-room limit
           Σ_τ ℓ^acc_τ(a) · o_τ ≥ max_v s^acc_v(a)   idem, for needs-accessible members
```

with `ℓ_τ(a) = min(cap_τ, m of every hard Room-scoped R2 on a, α_τ of every hard R3 on a)`,
`ℓ^acc_τ(a) = min(acc_τ, the same m, α^acc_τ of every hard R3 on a)`, `s_v(a)` / `s^acc_v(a)` the
number of participants (pins included) / needs-accessible participants with value `v`.
Every constraint is a necessary condition of §4 (a room holds at most `ℓ_τ(a)` members of one value),
so the optimum `C_S` — and the solver's best bound `LB ≤ C_S` when not proven — is a **lower bound
of the stage-1 cost**. Center-scoped R2, cuts and R6 are not modelled (weaker bound, still valid).
The selected set `R_S` = the first `o_τ` rooms of every type by index (pinned rooms first), which is
exactly the order the symmetry breaking of §4 imposes.

**Step E — evaluate the greedy assignment.** The greedy assignment (below) respects every hard
stage-1 constraint inside `R_S` (a center-scoped R2 limit is shared by the rooms of a center, so after
each placement the allowances of all rooms of that center are recomputed). If it is complete and step S was optimal, the §4 model is built over
`R_S` with every `n_{k,r}` fixed to the greedy count (domain `[g, g]`), plus `Cost ≥ LB`, and solved
for `SoftPenalty` (nothing is left to search; presolve is trivial). If that is feasible with penalty 0
and `Cost = LB`, it is the stage-1 result and it is **optimal** (cost = a lower bound, penalty = 0).
This is the common case: on large the open set is ~98 % full and R5 is 0.

**Step A — assignment on the selected rooms.** The §4 model is built with `y_r = 0` and no
`n_{k,r}` for `r ∉ R_S`, plus the redundant bound `Cost ≥ LB`. Hint: the previous solution when the
request has one (feedback re-solve), otherwise the greedy assignment. If step S was optimal the cost
is already fixed (`R_S` costs `C_S = LB`, and `Cost ≥ LB`), so only `SoftPenalty` is minimized;
otherwise the usual lexicographic solve (cost, then soft). Every solution found has `Cost ≥ LB`, so
`Cost = LB` proves the cost globally optimal. (Measured on large: CP-SAT presolve of this model —
~90 000 variables — alone takes ~20 s on 2 cores, which is why step E exists.)

Feedback re-solves (§6) run the same steps: the greedy assignment respects the cuts, so step E
usually answers again; the whole allocation may change, not only the cut rooms.

**Step C — global soft check.** Step A's soft optimum is only optimal among solutions inside `R_S`.
If its soft penalty is 0 (or there are no soft rules) it is globally optimal. Otherwise the full model
is solved with `Cost ≤ C*`, objective `SoftPenalty`, hinted with step A, in the remaining time; the
better solution is kept, `Optimal` only if that solve proves it.

**Step D — fallback.** If step A finds no solution (infeasible inside `R_S`, or time), the single
model of §4 is solved with the remaining time, with `Cost ≥ LB` and the greedy `y` hint.

Time split of `Stage1TimeLimitSeconds = T`: step S ≤ 0.1 T, step E ≤ 0.1 T, step A ≤ 0.5 T,
steps C/D the rest. Status `Optimal` iff step S was optimal, the cost is `LB`, and the soft part was
proven (penalty 0, or step C optimal).

**Greedy assignment** (`GreedyAssignment`, hint for step A). Rooms `R_S`; per room it tracks free
seats `cap_r − pin_r`, free accessible seats, and the count of every (key, value) — per room, and per
center for Center-scoped R2 — pins included. A participant of class `k` fits room `r` iff a seat is
free (an accessible one if `k` needs it), every hard R2 limit `m`, every hard R3 bound `α_r`
(`α^acc_r` for needs-accessible members) and every cut of `r` would still hold. Classes are placed
needs-accessible first, then by descending size of their largest limited value; each participant goes
to the fitting room with the most free seats (ties: lowest index), which balances fill and keeps R5
low. Rooms left empty get `y_r = 0`. If somebody fits nowhere the hint is still given (partial);
CP-SAT repairs it.

Measured (Bench, 2 shared cores, docs/benchmarks.md): large stage 1 0.7–1.5 s (was: no solution in
40 s, or all 400 rooms at cost 480 000), `Optimal` with 176 rooms at cost 204 100 = `LB`; medium stage 1
0.04–0.2 s (was 5–12 s), unchanged cost.

**Model size guardrail**: if |K| × |eligible rooms| > 2 000 000, emit `ModelTooLarge`
diagnostic and abort with a clear message (MVP; later: split by center). Stage 1 then returns
status `Failed`.

**Implementation details (WS-A)**

- Domains: `n_{k,r} ∈ [0, min(s_k, cap_r − pin_r)]`; for classes needing accessible seats also
  `≤ acc_r − pinAcc_r`. A pair with an upper bound of 0 gets no variable.
- Additional link: `Σ_k n_{k,r} + pin_r ≥ y_r` — an open room is never empty (keeps `RoomsUsed`,
  cost and R5 honest, notably in alternatives mode where cost is not minimized).
- Feedback cuts `Stage1Cut(r, a, v, m)` count pinned participants too:
  `Σ_{k: val_a(k)=v} n_{k,r} + pin_{a,v,r} ≤ m`.
- R6 is only modelled for values with `s_v ≥ 2` (incl. pinned); `pin_{v,c} > 0` forces `z_{v,c} = 1`.
- `CostThenSoft`: phase 2 is skipped when no soft rule exists; if phase 2 finds no solution
  the phase-1 solution is returned (status `Feasible`).
- **Alternatives mode** (`PreviousSolutions` non-empty): one solve, objective
  `minimize SoftPenalty`, with the diversity constraint of §8, `D` computed from the number of
  non-pinned participants (`Σ_k s_k`). `CostBound` (scaled ×100) adds `Cost ≤ CostBound` in any mode.
- `Hint` sets `AddHint` on `n_{k,r}` (and `y_r = [Σ_k n_{k,r} > 0]`).
- Status: `Optimal` only if every executed phase proved optimality; cancellation
  (`StopSearch`) yields `Cancelled` regardless of what was found.
- `ObjectiveBreakdown` of stage 1: `RoomsUsed = Σ y_r`, `Cost = Σ cost_r · y_r` (unscaled),
  `SoftPenalty` / `PenaltyByRule` = stage-1 penalties.

## 5. Stage 2 — seating inside a room (`Solver/Seating/`)

Rooms are independent: solved with `Parallel.ForEachAsync`, degree = `ProcessorCount`,
each model with `num_workers = 1`, time limit `Stage2TimeLimitSecondsPerRoom`.

Inputs per room: seats `P`, classes present `K_r` with counts `n_{k,r}` from stage 1, pinned
seats (fixed occupant class), pins with room only (treated as a class of size 1 with its own
attributes).

**Variables**: `u_{k,p} ∈ {0,1}` for `k ∈ K_r`, `p ∈ P` (only accessible seats if `k` needs them).

**Hard constraints**

1. `Σ_p u_{k,p} = n_{k,r}`.
2. `Σ_k u_{k,p} ≤ 1` (seat holds at most one); pinned seats: their class fixed to 1, others 0.
3. R3 hard, for each value `v` of attribute `a`, for each edge `(p,q) ∈ E_r(kinds)`:
   `A_{v,p} + A_{v,q} ≤ 1`, where `A_{v,p} = Σ_{k: val_a(k)=v} u_{k,p}` (0/1 by constraint 2).
   Only generate for values with total count ≥ 2 in this room.

**Soft**

- R3 soft: `viol_{v,p,q} ≥ A_{v,p} + A_{v,q} − 1`, penalty `w · Σ viol`.
- R8 `SpreadInRoom`: `occ_p = Σ_k u_{k,p}`; `pair_{p,q} ≥ occ_p + occ_q − 1` on its edges; penalty `w · Σ pair`.
- R9 `FillFromFront`: penalty `w · Σ_p row(p) · occ_p`.

**Objective**: minimize the sum of stage-2 penalties.

If a room has no R3/R8/R9 rule in play, skip CP-SAT: assign greedily in seat-key order
(accessible seats first for classes that need them).

Implementation notes (`SeatingSolver`, per room, stateless, safe to call concurrently):
- **Units**: every class with `n_{k,r} > 0`, plus every pin of the room as a unit of size 1
  carrying the pinned participant's attributes. A fixed-seat pin's unit has exactly one allowed
  seat (its own, accessibility not enforced — the pin wins); no other unit may use that seat.
  A pin on a missing/disabled or duplicated seat → `Infeasible`. Missing attribute value =
  unique (never conflicts).
- "R3 in play" = some value of the rule's attribute has total count ≥ 2 in the room (pins
  included). R8/R9 are in play whenever present. Previous seatings (alternatives) also force
  the CP-SAT path.
- **Greedy order**: fixed pins, then units needing accessible seats (in their accessible
  seats, key order), then the rest (classes by index; pins ordered by participant id first),
  each filling the first free allowed seats in key order. The greedy seating is also used as a
  CP-SAT hint.
- **Seat-level diversity** (§8 step 2): for each previous seating `j`, at least one previous
  `(unit, seat)` cell of a movable unit must change (`Σ kept ≤ cells − 1`, i.e. Hamming ≥ 2);
  applied only if the room has ≥ 2 movable units or spare allowed seats. If that makes the
  room infeasible, the room is re-solved without diversity (best effort; allocations are
  deduplicated by hash anyway).
- Status: CP-SAT `OPTIMAL/FEASIBLE/INFEASIBLE` map 1:1, `UNKNOWN` → `NoSolutionInTime`
  (`Cancelled` if the token fired), other → `Failed`. Greedy → `Optimal`.
- `PenaltyByRule` (soft R3, R8, R9; hard rules absent) is evaluated on the final seating,
  R9 including pinned occupants; `Penalty = Σ PenaltyByRule`.

## 6. Feedback loop (stage 2 infeasible)

When room `r` is infeasible in stage 2 with hard R3:
1. Let `v*` = the value of the hard R3 attribute with the largest count `c*` in `r`.
2. Add stage-1 cut `Σ_{k: val=v*} n_{k,r} ≤ c* − 1` and re-solve stage 1 with the previous
   solution as hint (only the affected rooms change in practice).
3. Repeat up to `MaxFeedbackIterations`; if still infeasible, return `Infeasible` with
   diagnostic `SeatingInfeasible` listing rooms and values.

This cut is heuristic (it can exclude feasible configurations) but always moves toward
feasibility. Expected to trigger rarely because of the α-bound.

Implementation notes (WS-A): `c*` includes pinned participants of `r` (the cut counts pins,
see §4). A room whose stage 2 returns `NoSolutionInTime` is treated like an infeasible one.
If several hard R3 rules exist, the (attribute, value) with the largest count is cut. If no
cut can be built (no hard R3 or `c* ≤ 1`) the pipeline stops with `SeatingInfeasible`
(arguments `RoomId`, `AttributeKey`, `Value`, `Size`). If stage 1 becomes infeasible only
after cuts were added, the result is also `SeatingInfeasible` (no conflict core).

## 7. Precheck and infeasibility explanation (`Solver/Precheck/`)

### 7.1 Precheck (fast, no CP-SAT except α)

| Code | Condition |
|---|---|
| `CapacityTotalExceeded` | participants > Σ cap of active rooms |
| `AccessibleCapacityExceeded` | needs-accessible participants > Σ acc |
| `SeparationImpossible` | hard R2: `size_v > m · (#scope units)` for some value `v` |
| `NoAdjacencyImpossible` | hard R3: `size_v > Σ_r α_r`, or `accSize_v > Σ_r α^acc_r` (needs-accessible members of `v`) |
| `PinInvalidSeat` | pin references a disabled/missing seat |
| `PinDuplicateSeat` | two pins on one seat |
| `PinRoomOverfull` | pins in a room exceed its capacity |
| `PinRuleConflict` | pins alone violate a hard R2/R3 |
| `AttributeMissing` (warning) | participants lacking a rule attribute |
| `NoActiveRooms` | no active rooms |

Each diagnostic carries a `DiagnosticCode` enum value and typed `Arguments`
(`DiagnosticArgument` enum keys: `AttributeKey`, `Value`, `Size`, `Limit`, `RoomId`, …).
The Ukrainian text is rendered from `Solver/Resources/Diagnostics.resx` (neutral language `uk`, rendered by `DiagnosticMessages.Render`) where the
resource name equals the enum member name — no message strings in code.

### 7.2 Conflict core (CP-SAT said INFEASIBLE)

Rebuild stage 1 with an **enforcement literal per hard rule** (`b_rule`, constraints
`OnlyEnforceIf(b_rule)`), plus a literal for capacity of each center (`b_cap_c`). Add all
literals as assumptions (`model.AddAssumptions`), solve, read
`solver.SufficientAssumptionsForInfeasibility()` → set of rules in conflict. Then minimize
the core by deletion (drop one literal, re-check, keep it out if still infeasible) within a
10 s budget. Output diagnostic `ConflictCore` with the list of rule ids and centers.

Implementation notes (WS-A): literals exist for hard R2 rules, hard R3 rules (α-bound), the R4
rule (if present in `Rules`; otherwise accessibility stays unconditional) and per-center
capacity. In this mode domains are not tightened by capacity or rules (`n_{k,r} ≤ s_k` only),
symmetry breaking, cuts, soft rules and objective are omitted, and the model is solved with
one worker. Arguments: `RuleIds` and `CenterId` (comma-separated, invariant format).

Fallback (Phase 3 H1, R-21): stage 1 already proved the full model infeasible, so the set of *all*
enforcement literals is a (non-minimal) core. When the assumption solve does not answer
`INFEASIBLE` within its limit (`UNKNOWN`), `Explain` emits `ConflictCore` with every hard rule and
center of the explain model and the extra argument `Reason = Unminimized`
(`ConflictCoreReason` enum name) instead of an empty list. (A core whose minimization is cut short
by its 10 s budget is reported as before, without `Reason`.) If the explain model is `FEASIBLE` (stage-1 infeasibility came from a part the explain model omits)
or the run was cancelled, nothing is emitted.

## 8. Alternatives (`Solver/Alternatives/`)

After the best allocation `A_0` (stage-1 counts `n⁰`):

For `i = 1..N`:
1. Stage 1 with extra constraints:
   - `Cost ≤ ⌈C* · (1 + CostSlack)⌉`;
   - diversity vs **every** previous solution `j`: `Σ_{k,r} |n_{k,r} − nʲ_{k,r}| ≥ 2·D`,
     `D = max(1, ⌈DiversityRatio · |P|⌉)` (each moved participant changes two cells), with
     `|·|` via `AddAbsEquality` on auxiliary ints;
   - objective: minimize `SoftPenalty`.
2. If stage 1 becomes infeasible (e.g. room assignment is forced), or finds no room-level alternative
   within its time limit while the alternatives budget is not used up, switch to
   **seat-level diversity**: keep `n⁰`, and in stage 2 require, per room, Hamming distance
   `Σ_p |A_{k,p} − Aʲ_{k,p}|` ≥ 2 vs previous seatings (only rooms with ≥ 2 classes), using
   a different random seed.
3. Stop early when no new distinct allocation is found or the overall time budget
   (`Stage1TimeLimitSeconds × 2`) is spent; return what was found with diagnostic
   `AlternativesLimited` (reason).

Allocations are deduplicated by a hash of sorted `(participantId, roomId, seatKey)`.

Implementation notes (WS-A): `IAlternativesGenerator.Generate` returns `AlternativesResult`
(allocations + diagnostics). The generator runs stage 2 + expansion itself (shared
`AllocationRealizer` with the pipeline) and applies its own feedback cuts (≤
`MaxFeedbackIterations` per alternative). Each stage-1 solve gets
`min(Stage1TimeLimitSeconds, remaining budget)`. Seat-level fallback uses
`RandomSeed + i` and passes all previous seatings of the room. `AlternativesLimited.Reason`
is an `AlternativesLimitReason` enum name (`TimeBudgetExhausted`, `NoDistinctAllocation`,
`Cancelled`). The pipeline validates every alternative and drops invalid ones
(`InternalValidationFailed` warning).

Phase 3 H1 (R-20): `AlternativesRequest.Cuts` carries the feedback cuts the pipeline learned for
`A_0`; every stage-1 alternative starts with them (they are rooms × values that stage 2 could not
seat, so re-discovering them would only cost re-solves). The budget `Stage1TimeLimitSeconds × 2`
covers the whole loop: a deadline token (linked to the caller's token) cancels stage 1 **and**
stage 2 when it is spent; before each realization the remaining time is checked, and the per-room
stage-2 limit is `min(Stage2TimeLimitSecondsPerRoom, ⌈remaining⌉)`. Hitting the deadline ends the
loop with `AlternativesLimited(TimeBudgetExhausted)`; the caller's cancellation still yields
`Cancelled`.

## 8a. Pipeline (`Solver/Pipeline/SolverPipeline`)

1. `Precheck` — any `Error` diagnostic → status `Infeasible` (no solving).
2. `ClassBuilder`.
3. Stage 1 (with cuts). `Infeasible` without cuts → `ConflictExplainer` → `Infeasible` +
   `ConflictCore`; `NoSolutionInTime`/`Failed` → returned as is.
4. Stage 2 per room (`Parallel.ForEachAsync`, degree `ProcessorCount`); failed rooms →
   feedback cuts (§6).
5. Expansion (alternative index 0).
6. Post-validation with `IAllocationValidator`; invalid → `Failed` + `InternalValidationFailed`.
7. Alternatives (if `Options.Alternatives > 0`).
8. Status `Optimal` iff stage 1 and every room of stage 2 were optimal, else `Feasible`.

Final `ObjectiveBreakdown`: `RoomsUsed`/`Cost` from the rooms that actually hold participants,
`SoftPenalty`/`PenaltyByRule` = stage-1 + stage-2 penalties. Cancellation at any point →
`Cancelled` (no allocations). Progress is reported at each `SolveStage` change, per room in
stage 2 (`RoomsDone`/`RoomsTotal`) and per alternative (`AlternativesDone`).

## 9. Expansion (`Solver/Expansion/Expander`)

For each room and class: participants of the class sorted by `SortKey`, seats of the class
sorted by seat key (row, column, seat) → zip. Alternatives with `i > 0` shuffle participants
within a class using `Random(RandomSeed + i)` so that alternatives also differ individually.

Precisely: each class becomes one queue of its members ordered by (`SortKey` ordinal,
participant id), Fisher–Yates-shuffled (`Random.Shuffle`, classes in index order) when `i > 0`.
Rooms are visited in `RoomId` order and seats inside a room in (row, column, seat) order; each
class seat dequeues the next member, so a class split across rooms is chunked in room order.
Pinned seats (`PinnedParticipantId`) are emitted unchanged. More class seats than members →
`InvalidOperationException` (internal error).

## 10. Independent validator (`Solver/Validation/AllocationValidator`)

A **separate, straightforward implementation** (no CP-SAT) that checks a full allocation
against the input: every participant seated exactly once, seats unique and enabled,
capacity, accessibility, pins, hard R2/R3 (by brute force over pairs/edges), and computes
soft penalties. Returns `ValidationReport { IsValid, Violations[], Penalties }`.

Used by:
- the pipeline as a post-condition (a violation → `Failed` with `InternalValidationFailed`);
- the API when the user manually edits an allocation;
- all solver tests as the oracle.

It must be written by a different agent than the CP model (see 09) so that the model is not
grading itself.

Validator semantics (binding for the CP model as well):
- `SameDesk` adjacency is always on for R3 **and** R8, whatever `kinds` lists (03 "always on").
- `SeatLevelSide` refines `Side` only, not `SideAcrossAisle`.
- R5 uses `⌈ratio · cap − 1e-9⌉` and applies to used rooms only.
- R5/R6/R8/R9 are soft regardless of `IsHard`; R4 is always hard, and accessibility is checked
  even when no R4 rule exists.
- `Penalties.PenaltyByRule` contains every enabled soft rule (also with 0) and no hard rule.
- Attribute values that are absent or whitespace are "missing": such a participant forms a
  value of its own (never conflicts with anyone).
- An assignment whose participant is not in the input is `UnknownParticipant` (hard); an unknown
  room or a missing/disabled seat is `SeatNotFound` (hard).

## 11. CP-SAT parameters

```
num_workers           = Options.NumWorkers (0 → Environment.ProcessorCount)   // stage 1
max_time_in_seconds   = per stage as above
random_seed           = Options.RandomSeed
log_search_progress   = true only when env EXAM_SOLVER_LOG=1
```

One builder, `Solver/Layout/CpSatParameters.Build`, produces the parameter string for every model
(stage 1, conflict core, stage 2, α); `Allocation/CpSat` keeps only worker resolution, status mapping
and the cancellable solve (R-22). Time limits below 0.05 s are raised to 0.05 s.

Progress: a `CpSolverSolutionCallback` subclass reports objective/bound at most every 500 ms.
Cancellation: `CancellationToken.Register(() => solver.StopSearch())`.

**Determinism caveat for tests**: with multiple workers and time limits, assignments can
differ between runs. Tests assert **properties** via the validator and objective values on
small instances solved to optimality — never exact seat assignments, except for the
greedy path and the expander.
