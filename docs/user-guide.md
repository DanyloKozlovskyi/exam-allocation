# Посібник адміністратора тестування

Цей посібник описує повний цикл роботи в застосунку «Розподіл учасників тестування»: від створення
сесії до експорту готових відомостей. Назви кнопок, вкладок і полів наведено так, як їх видно в інтерфейсі
(у лапках «…»).

> Як запустити застосунок локально, описано в [README](../README.md#quick-start). Далі вважаємо, що
> інтерфейс відкрито за адресою http://localhost:3000.

## 1. Загальна схема роботи

```
Сесія → Центри → Аудиторії → Учасники → Правила → Розрахунок → Результати → Експорт
```

Ліва панель навігації повторює цей порядок: «Сесії», «Огляд», «Центри», «Аудиторії» (з'являється, коли
відкрито конкретний центр), «Учасники», «Правила», «Розрахунок», «Результати» (з'являється після першого
успішного розрахунку). Біля пунктів показано лічильники (кількість центрів, аудиторій, учасників, правил,
розрахунків).

Система не перебирає «усі можливі розсадки» (їх астрономічно багато). Вона знаходить **один найкращий
розподіл** і кілька **альтернатив**, що помітно відрізняються від нього, або пояснює, чому розмістити
учасників за заданими правилами неможливо.

## 2. Сесія тестування

**Сесія** — це одна подія тестування; усі центри, аудиторії, учасники, правила й результати належать
певній сесії.

1. Відкрийте «Сесії» → «Нова сесія».
2. Крок «Основні дані»: «Назва» (обов'язково), «Дата тестування», «Опис».
3. Крок «Підсумок» → «Створити сесію».

Після створення відкривається сторінка «Огляд сесії»:

- **«Показники»** — кількість центрів, активних аудиторій, «Місткість», «Доступні місця», учасників,
  тих, хто «Потребують доступного місця», груп і правил.
- **«Підготовка до розрахунку»** — чек-лист: «Додано центри тестування», «Додано аудиторії»,
  «Імпортовано учасників», «Місткості достатньо для всіх учасників», «Достатньо доступних місць»,
  «Налаштовано правила розміщення». Кожен пункт позначено «Виконано» або «Потребує уваги», поруч —
  кнопка «Перейти».
- **«Останній розрахунок»** — статус останнього запуску з посиланнями «Відкрити» та «Результати».
- Якщо після розрахунку змінилися вхідні дані, з'являється попередження «Вхідні дані змінилися після
  останнього розрахунку — результати застаріли.» (див. [§9.6](#96-застарілі-результати)).

Редагувати сесію — кнопка «Редагувати». Видалення сесії зі списку «Сесії тестування» безповоротно
видаляє також центри, учасників і результати.

## 3. Центри тестування

**Центр** — будівля, у якій є аудиторії. Відкрийте «Центри».

### Додавання центру

- **З мапою Google** (якщо в налаштуваннях вказано ключ Google Maps): знайдіть будівлю в полі «Пошук місця
  (Google Places)» або клацніть на мапі — відкриється форма нового центру з уже заповненими назвою,
  адресою та координатами.
- **Без мапи** (ключ не налаштовано): замість мапи показано блок «Мапа недоступна». Введіть «Широта» і
  «Довгота» (наприклад, 50.4501 і 30.5234) та натисніть «Додати центр у цій точці».
- Або кнопка «Додати центр» — порожня форма.

Форма «Новий центр тестування» (кроки «Основні дані» → «Підсумок»):

| Поле | Значення |
|---|---|
| «Назва», «Адреса» | як буде видно у відомостях |
| «Широта», «Довгота» | координати для мапи результатів |
| «Вартість аудиторії» | «Порожнє значення — вартість за замовчуванням» (1). Розрахунок прагне відкрити якомога дешевший набір аудиторій, тож вища вартість робить аудиторії цього центру менш бажаними |
| «Активний» | неактивний центр і всі його аудиторії не беруть участі в розрахунку |

Список «Центри тестування» показує кількість аудиторій і місткість кожного центру. Перемикач «Активний»
вмикає/вимикає центр прямо зі списку. Дія «Аудиторії» в рядку відкриває аудиторії цього центру.

## 4. Аудиторії

Відкрийте «Центри» → дія «Аудиторії» в рядку центру → «Додати аудиторію». Майстер має три кроки.

### Крок «Параметри»

| Поле | Значення |
|---|---|
| «Назва» | наприклад, «Ауд. 214» |
| «Ряди» | ряди парт (1–30); ряд 1 — найближчий до дошки / столу екзаменатора |
| «Парт у ряду» | 1–20 |
| «Місць за партою» | 1–3 |
| «Проходи після парт» | позначте «Після парти N», якщо між партою N і N+1 є прохід. Прохід впливає на те, які місця вважаються сусідніми (див. [§6.3](#63-види-сусідства)) |
| «Вартість аудиторії» | «Порожнє значення — вартість центру» |
| «Активна» | неактивні аудиторії не використовуються в розрахунку |

### Крок «План»

Показано схему аудиторії («Дошка / стіл екзаменатора» зверху). **Натисніть на місце, щоб змінити його стан:
звичайне → для осіб з інвалідністю → недоступне.**

- **Для осіб з інвалідністю (доступне місце)** — сюди система садить учасників з позначкою «Особливі
  потреби». Інших учасників на такі місця теж можна садити.
- **Недоступне** — місця фізично немає або ним не можна користуватися (зламана парта тощо); воно не
  входить у місткість.

Під схемою — «Місткість: …, з них для осіб з інвалідністю: …». Перемикач «Показати сусідство» підсвічує,
які місця вважаються сусідніми для кожного виду сусідства — зручно перевірити, чи правильно вказані проходи.

### Крок «Підсумок» і створення кількох однакових аудиторій

На підсумковому кроці поле **«Кількість копій»** («Створити кілька однакових аудиторій з цим планом»,
1–50) дозволяє одним рухом створити багато аудиторій з однаковим планом. Кнопка тоді називається
«Створити аудиторії (N)», а назви отримують номер: «Ауд-1», «Ауд-2», … Кожну копію потім можна
перейменувати чи змінити окремо.

### Редагування

«Редагувати» відкриває той самий майстер. Якщо нова схема прибирає місце, на якому зафіксовано учасника,
збереження буде відхилено з повідомленням «Зміна плану видаляє місця, на яких зафіксовані учасники.»

## 5. Учасники та імпорт

### 5.1 Підготовка файлу

Підтримуються файли **.xlsx** і **.csv** розміром до 20 МБ (до 100 000 рядків). Найпростіше взяти шаблон:
кнопка «Завантажити шаблон» у майстрі імпорту (той самий файл — `samples/participants-template.xlsx`).

| Колонка | Обов'язкова | Примітка |
|---|---|---|
| ID | ні | ідентифікатор з вашої системи; має бути унікальним |
| Прізвище, Ім'я | так | або одна колонка «ПІБ» — вона буде розділена за пробілами |
| По батькові | ні | |
| Група | ні* | *потрібна, якщо правила розміщення використовують групу |
| Навчальний заклад | ні | |
| Особливі потреби | ні | «так/ні», «yes/no», «1/0», «+/-»; порожнє = ні |
| Примітки | ні | |
| будь-яка інша колонка | ні | імпортується як **додатковий атрибут** (наприклад, «Профіль»), який можна використати в правилах |

CSV: роздільник `;`, `,` або табуляція визначається автоматично; кодування UTF-8 (або Windows-1251).

### 5.2 Майстер «Імпорт учасників»

«Учасники» → «Імпорт з файлу». Кроки:

1. **«Файл»** — «Обрати файл» → «Завантажити».
2. **«Аркуш і заголовок»** — оберіть «Аркуш» (для xlsx з кількома аркушами) і «Номер рядка заголовка»
   («Рядок, у якому містяться назви колонок»), якщо над таблицею є шапка документа. Нижче — «Перші рядки
   файлу» для контролю.
3. **«Відповідність колонок»** — для кожного поля учасника («Поля учасника») оберіть колонку файлу.
   Система заздалегідь підставляє відповідності за назвами колонок (у т. ч. «Фамилия», «Клас», «Школа»,
   «Surname» тощо). «— не імпортувати —» пропускає поле. У блоці «Додаткові атрибути» колонки без поля
   можна імпортувати як атрибути й задати їм «Ключ атрибута». Потрібно вказати «Прізвище» та «Ім'я» або
   «ПІБ»; одну колонку не можна обрати для кількох полів.
4. **«Перевірка»** — підсумок «Коректних рядків», «Рядків з помилками», «Дублікатів» і таблиця помилок
   («Рядок», «Колонка», «Помилка»):

   | Помилка | Що означає |
   |---|---|
   | «Не заповнено обов'язкове поле» | порожні прізвище або ім'я |
   | «Значення задовге» | перевищено допустиму довжину |
   | «Не вдалося розпізнати так/ні» | у «Особливі потреби» незрозуміле значення |
   | «Дублікат у файлі» | той самий ID (або ПІБ при пошуку дублікатів за ПІБ) трапляється двічі; імпортується перший рядок |
   | «Учасник уже є в сесії» | рядок збігається з наявним учасником — його дані буде **оновлено** (не помилка); якщо ж ID належить іншому учасникові — рядок відхиляється |
   | «Некоректний ключ атрибута» | невдалий ключ додаткового атрибута — змініть його на кроці відповідності |

   Порожні рядки пропускаються мовчки.
5. **«Режим»**:
   - «Що робити з наявними учасниками»: «Додати до наявних» або «Замінити всіх учасників сесії»;
   - «Як визначати дублікати»: «Не перевіряти», «За ID», «За ПІБ»;
   - «Пропустити рядки з помилками» — без цієї позначки файл з помилками імпортувати не можна.
6. **«Імпорт»** — перевірте «Підсумок» і натисніть «Імпортувати». Результат: «Додано», «Оновлено»,
   «Пропущено». Імпорт атомарний: або всі коректні рядки, або нічого. «До списку учасників» повертає до
   списку.

### 5.3 Список учасників

Таблиця «Учасники» з пошуком «Пошук за ПІБ або ID» і фільтрами «Група», «Навчальний заклад», «Доступне
місце» («Усі» / «Потребують» / «Не потребують»). Додаткові атрибути показано окремими колонками. Значення
можна виправити прямо в клітинці (подвійне клацання), учасника — видалити; «Видалити всіх» очищає список
сесії.

## 6. Правила розміщення

«Правила» → «Додати правило». Майстер: «Тип і вага» → «Параметри» → «Підсумок».

### 6.1 Обов'язкові та бажані правила

- **«Обов'язкове»** — має виконуватися завжди. Якщо його неможливо виконати, розрахунок завершиться
  статусом «Неможливо розмістити» з поясненням.
- **«Бажане»** — система намагається його виконати, а кожне порушення додає **штраф**. «Вага» (1–1000;
  «чим більша, тим важливіше правило») множить штраф. Наприклад, бажане правило з вагою 100 система
  порушить значно неохочіше, ніж з вагою 1.

Деякі типи бувають лише одного виду — недоступний варіант у майстрі вимкнено. Перемикач «Увімкнене»
дозволяє тимчасово вимкнути правило без видалення (також у списку правил). «Назва (необов'язково)»
показується у списку, у діагностиці та у штрафах.

Завжди діють і неявні обов'язкові вимоги: кожен учасник отримує рівно одне місце, місткість аудиторії не
перевищується, фіксації (див. [§10](#10-ручне-редагування-та-фіксації)) виконуються, учасник з особливими
потребами сидить на доступному місці.

### 6.2 Типи правил

| Тип | Вид | Параметри | Простими словами |
|---|---|---|---|
| «Розділяти за атрибутом» | обов'язкове або бажане | «Атрибут», «Межа» («Аудиторія» або «Центр тестування»), «Не більше учасників з однаковим значенням» | Не більше N учасників з однаковим значенням (наприклад, однієї групи) в одній аудиторії / одному центрі. Приклад: група, аудиторія, ≤ 4 |
| «Не садити поруч однакових» | обов'язкове або бажане | «Атрибут», «Вважати сусідами» (види сусідства), «Лише безпосередньо сусідні місця сусідніх парт» | Учасники з однаковим значенням (наприклад, одногрупники) не сидять поруч. За однією партою — ніколи, решта видів — за вибором |
| «Місця для осіб з інвалідністю» | лише обов'язкове | немає | Учасники з «Особливі потреби» сидять на місцях, позначених як доступні. Ця вимога діє, навіть якщо правило не додано |
| «Мінімальне заповнення аудиторій» | лише бажане | «Мінімальне заповнення аудиторії, %» | Відкриту аудиторію заповнювати щонайменше на X % (не відкривати аудиторію заради 2–3 осіб). Штраф — за кожне недостатнє місце |
| «Тримати разом в одному центрі» | лише бажане | «Атрибут» | Учасники з однаковим значенням (наприклад, з одного закладу) потрапляють до одного центру. Штраф — за кожен додатковий центр |
| «Розсаджувати рідше» | лише бажане | «Вважати сусідами» | Менше зайнятих сусідніх місць (коли місць більше, ніж учасників) |
| «Заповнювати з перших рядів» | лише бажане | немає | Спершу заповнюються ряди, ближчі до екзаменатора |

**Атрибут** — це «Група», «Навчальний заклад» або будь-який додатковий атрибут з імпорту; у списку видно
кількість різних значень. Учасник **без значення** атрибута ні з ким не конфліктує за цим правилом
(перевірка покаже попередження «Відсутні значення атрибута»).

### 6.3 Види сусідства

Позначки «Вважати сусідами» (з ілюстраціями в майстрі):

| Вид | Які місця сусідні |
|---|---|
| «За однією партою» | місця за однією партою — **увімкнено завжди** |
| «Сусідні парти в ряду» | парти поруч в одному ряду без проходу між ними |
| «Через прохід» | парти поруч в одному ряду, між якими є прохід |
| «Спереду / позаду» | парта безпосередньо попереду або позаду |
| «По діагоналі» | парти по діагоналі (без проходу між колонками) |

«Лише безпосередньо сусідні місця сусідніх парт» звужує «Сусідні парти в ряду»: сусідами вважаються лише
два місця, що торкаються одне одного (праве місце лівої парти й ліве місце правої).

Що більше видів сусідства обрано для обов'язкового правила, то менше учасників однієї групи вміщається в
аудиторію — і то вища ймовірність, що розмістити всіх не вдасться.

## 7. Перевірка здійсненності

У «Правила» натисніть **«Перевірити здійсненність»**. Швидка перевірка (кілька секунд) шукає очевидні
перешкоди ще до розрахунку й показує панель «Результати перевірки»: або «Проблем не виявлено», або список
повідомлень. Кожне має назву, рівень («Інформація», «Попередження», «Помилка»), текст, блок «Що зробити» та
рядок «Де виправити» з посиланнями туди, де причину можна усунути: «Правило «…»», «Аудиторії центру «…»»,
«План аудиторії «…»», «Центри та аудиторії», «Учасники: Група = «…»» (список одразу відфільтрований),
«Учасники, яким потрібне доступне місце», «Імпорт учасників», «Зафіксовані учасники». Якщо назву правила чи
центру визначити не вдалося, посилання має загальний підпис «Перейти до правила» / «Перейти до центру».

| Повідомлення | Причина | Що зробити |
|---|---|---|
| «Недостатньо місць» | учасників більше, ніж місць в активних аудиторіях | додати аудиторії/центри, активувати неактивні, зменшити кількість учасників |
| «Недостатньо доступних місць» | учасників з особливими потребами більше, ніж доступних місць | позначити більше доступних місць у планах аудиторій |
| «Розділення неможливе» | значень одного атрибута забагато для «Розділяти за атрибутом» (напр., група з 40 осіб, ≤ 4 на аудиторію, а аудиторій 8) | збільшити допустиму кількість, змінити межу на центр або зробити правило бажаним |
| «Неможливо уникнути сусідства» | навіть у найрідшій розсадці учасникам однієї групи не вистачає несусідніх місць | вимкнути частину видів сусідства, додати аудиторії або зробити правило бажаним |
| «Фіксація на неіснуюче місце», «Два учасники зафіксовані на одному місці», «Забагато фіксацій в аудиторії», «Фіксації суперечать правилу» | проблеми з фіксаціями | змінити фіксації або послабити правило |
| «Відсутні значення атрибута» (попередження) | у частини учасників немає значення атрибута, що використовується в правилі | доповнити дані; розрахунок можливий |
| «Немає активних аудиторій» | усі аудиторії / центри неактивні | активувати хоча б одну аудиторію |

Помилки рівня «Помилка» гарантовано зроблять розрахунок неможливим; попередження — ні. Відсутність
повідомлень не гарантує успіху: деякі конфлікти виявляються лише під час розрахунку (див. [§12](#12-усунення-проблем)).

## 8. Запуск розрахунку

«Розрахунок» → **«Запустити розрахунок»** → діалог «Параметри розрахунку»:

| Поле | За замовчуванням | Значення |
|---|---|---|
| «Кількість альтернатив» | 5 | 0–20; скільки додаткових варіантів шукати крім найкращого |
| «Ліміт часу, с» | 60 | 5–3600; час на основний етап (розподіл по аудиторіях). Для великих сесій (тисячі учасників) збільште |
| «Додаткові параметри» → «Режим цільової функції» | «Спершу вартість, потім побажання» | «Спершу вартість, потім побажання» — спочатку мінімальна вартість (найменше / найдешевші аудиторії), а серед таких — найменший штраф бажаних правил. «Зважена сума» — вартість і штрафи оптимізуються разом, тож дуже важливе бажане правило може «окупити» додаткову аудиторію |
| «Мінімальна відмінність альтернатив, %» | 10 | яка частка учасників має пересісти в кожній альтернативі порівняно з попередніми |
| «Допустиме подорожчання альтернатив, %» | 10 | наскільки альтернатива може бути дорожчою за найкращий варіант |
| «Початкове значення генератора (seed)» | 42 | зміна дає інші (але рівноцінні) варіанти розсадки |

«Запустити» — розрахунок ставиться в чергу й відкривається сторінка «Розрахунок від …». Для сесії
одночасно може виконуватися лише один розрахунок («Для цієї сесії вже виконується розрахунок.»).

### Перебіг розрахунку

Сторінка оновлюється наживо («Оновлення в реальному часі»; якщо з'єднання недоступне — «Оновлення кожні N с»):

- кроки: «Попередня перевірка» → «Розподіл по аудиторіях» → «Розсадка по місцях» (→ «Уточнення», якщо
  розсадку в якійсь аудиторії довелося перерахувати) → «Формування результату» → «Альтернативи» → «Готово»;
- відсоток, «Аудиторій оброблено: X з Y», «Знайдено альтернатив: N»;
- «Цільова функція» і «Межа» (найкраще досягнуте значення та теоретична межа; що ближче, то ближче до
  оптимуму) та графік «Динаміка цільової функції»;
- «Скасувати розрахунок» — зупиняє розрахунок, проміжні результати не зберігаються.

Сторінку можна закрити: розрахунок продовжиться на сервері, а список «Розрахунки» покаже його статус
(«У черзі», «Виконується», «Успішно», «Неможливо розмістити», «Помилка», «Скасовано»), тривалість і
кількість варіантів.

Після завершення в блоці «Результати» з'являються посилання «Найкращий варіант», «Варіант 1», … та
«Ручна версія» (якщо її збережено), а також «Статистика» (розмір задачі).

## 9. Перегляд результатів

Відкрийте результат зі сторінки розрахунку, з «Огляд сесії» («Результати») або з пункту «Результати» в
навігації. Сторінка «Результат розподілу — …».

### 9.1 Альтернативи

Вкладки вгорі — «Найкращий», «Варіант 1», … , «Ручна версія», під кожною — «Аудиторій: … · вартість: … ·
штраф: …». Порівнюйте варіанти й обирайте зручніший: усі вони виконують обов'язкові правила.

### 9.2 Вкладка «Огляд»

- **«Центри тестування»** — мапа (або список центрів без ключа Google Maps), колір маркера показує
  заповненість центру. Клацання по центру фільтрує список аудиторій; повторне клацання по тому самому
  центру скидає фільтр.
- **«Аудиторії»** — смуги заповнення «зайнято / місткість»; невикористані аудиторії позначено
  «не використовується». Клацання по аудиторії відкриває її розсадку.
- **«Штрафи за бажаними правилами»** — штраф кожного бажаного правила або «Бажані правила виконано без
  штрафів».

### 9.3 Вкладка «Учасники»

Таблиця «хто де сидить»: ПІБ, «Група», «Навчальний заклад», «Центр», «Аудиторія», «Місце» (ряд, парта,
місце). Поле «Пошук за прізвищем, ім'ям або групою».

### 9.4 Розсадка в аудиторії

Сторінка «<аудиторія> — розсадка» («Зайнято X з Y місць»): схема з прізвищами, колір — група (легенда
«Групи»), підказка при наведенні — повне ім'я, група, заклад, місце. Блок «Порушення» перелічує порушення
бажаних правил у цій аудиторії (наприклад, «Сусіди з однаковим значенням», «Не заповнено перші ряди») або
«Порушень немає»; місця з порушеннями підсвічено. «До результату» — повернення.

### 9.5 Розрахунки й історія

Список «Розрахунки» зберігає всі запуски сесії; старі результати залишаються доступними.

### 9.6 Застарілі результати

Зміна вхідних даних, що впливає на розрахунок (склад і активність центрів та аудиторій, плани, вартість,
учасники та їхні атрибути, правила, фіксації), робить результат **застарілим**; зміна лише назв, адрес чи
приміток — ні. Ознаки: у списку розрахунків — позначка «Дані змінилися», на сторінці розрахунку —
«Дані сесії змінилися після цього розрахунку — результат може бути неактуальним.», в огляді сесії —
відповідне попередження. Застарілий результат можна переглядати й експортувати, але перед остаточним
експортом варто запустити розрахунок знову.

## 10. Ручне редагування та фіксації

### 10.1 Ручні переміщення

На сторінці розсадки ввімкніть **«Ручне редагування»**:

1. «Оберіть учасника, якого потрібно пересадити.» — клацніть по зайнятому місцю.
2. «Оберіть нове місце (зайняте місце — обмін).» — клацніть по вільному місцю або по місцю іншого
   учасника (вони поміняються місцями).
3. Повторіть для інших переміщень; список «Змін: N» показує їх у вигляді «ПІБ: звідки → куди».
4. **«Перевірити зміни»** — система перевіряє нову розсадку за всіма правилами: «Зміни не порушують
   обов'язкових правил. Штраф: …» або «Зміни порушують обов'язкові правила (N). Штраф: …».
5. **«Зберегти як ручну версію»** — зберігає новий варіант «Ручна версія» (вихідний варіант не змінюється)
   і відкриває його. Якщо зміни порушують обов'язкові правила, з'явиться запит «Зберегти з порушеннями?» —
   так можна свідомо зберегти виняток.

«Скинути зміни» скасовує всі незбережені переміщення.

### 10.2 Фіксації та повторний розрахунок

**Фіксація** закріплює учасника за місцем: при наступному розрахунку він залишиться там, а решта
учасників буде розподілена навколо нього.

- **«Зафіксувати все»** (сторінка результату) — фіксує всіх учасників цього варіанта на їхніх місцях.
- **«Зафіксувати аудиторію»** (сторінка розсадки) — лише учасників цієї аудиторії.

Після фіксації відразу відкривається діалог «Параметри розрахунку» для повторного запуску. Типовий сценарій:
відкоригувати аудиторію вручну → зберегти ручну версію → «Зафіксувати аудиторію» → додати/змінити учасників
чи правила → запустити розрахунок знову. Фіксації змінюють вхідні дані, тож попередні результати стануть
застарілими.

**Перегляд і зняття фіксацій.** Пункт меню «Фіксації» відкриває сторінку «Зафіксовані учасники»: учасник,
аудиторія (посилання на її план) і місце («будь-яке місце», якщо закріплено лише аудиторію). Кнопка «Зняти
фіксацію» в рядку знімає одну фіксацію, «Зняти всі фіксації» — усі одразу (з підтвердженням). Повторна
фіксація переписує попередню для того самого учасника. Діагностики про фіксації ведуть саме на цю сторінку.

## 11. Експорт

Меню «Експорт» на сторінці результату (експортується вибраний варіант):

| Формат | Вміст |
|---|---|
| «Excel (XLSX)» | аркуш «Зведення» (сесія, дата, показники, підсумки центрів), аркуш «Усі учасники» (ПІБ, група, заклад, центр, адреса, аудиторія, ряд, парта, місце; з фільтром) і по аркушу на кожну аудиторію — список і схема розсадки |
| «XML» | повний розподіл для інших систем; схема `samples/allocation.xsd` |
| «CSV» | ті самі колонки, що «Усі учасники»; UTF-8, роздільник `;` (відкривається в Excel) |
| «PDF (відомості)» | для кожної аудиторії: схема з прізвищами та алфавітний список з колонкою для підпису |

На сторінці розсадки є «PDF для цієї аудиторії». Ряди, парти й місця у файлах нумеруються з 1.

## 12. Усунення проблем

### 12.1 «Неможливо розмістити»

Статус «Неможливо розмістити» означає, що за поточних даних і **обов'язкових** правил розподілу не існує
(або його не вдалося побудувати). На сторінці розрахунку показано «Результати перевірки» з тими самими
повідомленнями, що й у [§7](#7-перевірка-здійсненності), а також:

| Повідомлення | Що означає | Що зробити |
|---|---|---|
| «Правила суперечать одне одному» | система знайшла мінімальний набір обов'язкових правил (і, можливо, місткість центрів), які разом невиконувані; правила перелічено з посиланнями | вимкнути одне з указаних правил або зробити його бажаним, послабити параметри, додати місця |
| «Не вдалося розсадити в аудиторії» | розподіл по аудиторіях знайдено, але в зазначеній аудиторії неможливо посадити учасників одного значення атрибута без сусідства (повідомлення називає аудиторію, значення й кількість) | послабити правило сусідства, додати місця чи аудиторії, змінити план (проходи) |
| «Задача завелика» | забагато комбінацій атрибутів × аудиторій | використовувати менше атрибутів у правилах або розділити сесію за центрами |

Порядок дій: усуньте помилки з панелі → «Перевірити здійсненність» → запустіть розрахунок знову. Найчастіші
причини — замало доступних місць, надто суворе «Розділяти за атрибутом» (≤ 1–2) або «Не садити поруч
однакових» з усіма видами сусідства при щільному заповненні аудиторій.

### 12.2 Статус «Помилка»

Розрахунок не завершився через технічну причину. На сторінці розрахунку з'являється повідомлення з назвою
причини та порадою, а в списку розрахунків — стовпець «Причина»:

| Повідомлення | Що трапилося | Що зробити |
|---|---|---|
| «Розрахунок перервано» | сервер перезапустили під час розрахунку або коли розрахунок був у черзі | кнопка «Запустити повторно» — дані сесії не постраждали |
| «Рішення не знайдено за відведений час» | за «Ліміт часу, с» не знайдено жодного допустимого розподілу (це не доводить, що його немає) | збільште ліміт часу, зменшіть кількість альтернатив або послабте обов'язкові правила; поруч є посилання на правила |
| «Помилка розв'язувача» | непередбачена внутрішня помилка; під повідомленням — «Подробиці: …» | повторіть розрахунок; якщо помилка повторюється — передайте подробиці розробникам |

### 12.3 Інші ситуації

| Ситуація | Пояснення |
|---|---|
| «Знайдено менше альтернатив» | альтернатив знайдено менше, ніж замовлено: варіанти, відмінні на задану частку, не вміщаються в допустиме подорожчання або вичерпано час. Збільште «Допустиме подорожчання альтернатив, %» або ліміт часу, зменште «Мінімальна відмінність альтернатив, %» |
| «Внутрішня помилка перевірки» | знайдений варіант не пройшов незалежну перевірку і був відкинутий; повторіть розрахунок |
| Розрахунок «Успішно», але є штрафи | бажані правила не вдалося виконати повністю; див. «Штрафи за бажаними правилами» та «Порушення» в аудиторіях; збільште вагу важливих правил |
| «Дані змінив інший користувач. Оновіть сторінку.» | запис змінено в іншій вкладці — оновіть сторінку й повторіть дію |
| «Імпорт не знайдено або він застарів.» | завантажений файл зберігається обмежений час (60 хв) — почніть імпорт заново |
| «Файл завеликий.» / «Файл не вдалося прочитати.» | перевірте розмір (до 20 МБ), формат (.xlsx / .csv) і що файл не захищено паролем |
| Мапа не показується | не налаштовано ключ Google Maps — користуйтеся формою координат; решта функцій працює |

## 13. Словник термінів

| Термін | Значення |
|---|---|
| Сесія тестування | одна подія тестування, що об'єднує всі дані |
| Центр тестування | будівля з аудиторіями, точка на мапі |
| Аудиторія | приміщення з планом парт і місць |
| Парта / місце | парта стоїть у ряду; за партою 1–3 місця |
| Учасник | особа, яку потрібно розмістити |
| Атрибут | властивість учасника: група, навчальний заклад або додаткова колонка з файлу |
| Правило | вимога до розміщення: обов'язкова або бажана (з вагою) |
| Сусідство | які місця вважаються «поруч» для правил |
| Фіксація | закріплення учасника за місцем на наступні розрахунки |
| Розрахунок | один запуск оптимізації |
| Розподіл / варіант | повна розсадка: учасник → центр → аудиторія → місце |
| Альтернатива | додатковий варіант, помітно відмінний від найкращого |
| Вартість | сума вартостей відкритих аудиторій; що менша, то економніше |
| Штраф | сума порушень бажаних правил з урахуванням ваги |
